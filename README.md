# Проект «АЛЬТЕРНАТИВА» и приложение АЛТ‑эксперт

Проект **«АЛЬТЕРНАТИВА»** помогает бизнесу и сообществам **адаптироваться к изменениям регуляторики** информационного пространства (российские мессенджеры и соцсети, требования к каналам, персональным данным и смежным темам). В репозитории — код веб‑приложения **АЛТ‑эксперт**, парсера, контент‑конвейера и связанной инфраструктуры.

**Стадия:** MVP — функционал и наполнение дорабатываются.
---

## Состав системы

1. **Сайт проекта** — [https://rusalts.ru/](https://rusalts.ru/). Размещение на **Timeweb Cloud**, настроен **HTTPS (SSL)**. Публичные страницы, новости, материалы.
2. **Чат‑бот на сайте** — встроенный диалоговый интерфейс на страницах сайта (общение с бэкендом через API).
3. **АЛТ‑эксперт** — ИИ‑ассистент по профильной тематике: **чат**, **загрузка вложений (документов)**, **выдача шаблонов документов**, опора на **базу знаний** и внешние источники по правилам маршрутизации. Веб‑интерфейс: [https://rusalts.ru/consultant](https://rusalts.ru/consultant). Подготовлены эндпоинты и переменные для **официальных приложений ВКонтакте** (см. `GET /widget`, `vidget_vk.md`, секреты VK в `.env` на сервере).
4. **Конвейер «получение → обработка → размещение»** — **парсинг** профильных сайтов, **обработка** (в т.ч. через LLM), обновление **базы знаний** (`knowledge_base/`), подготовка **новостей и релизов** для **сайта** и **сообщества ВКонтакте «АЛЬТЕРНАТИВА»**. Тематика публикуемого контента **ограничена профилем проекта**. Согласование и публикация: страница **`/publapprov/`** (режим `CONTENT_APPROVAL_MODE=web`), фоновые воркеры `parser-worker` и `content-worker`, очередь на **Redis**.
5. **Автодеплой** — изменения из **GitHub** доставляются на сервер и поднимаются через **Docker Compose** (см. `deploy/DEPLOY_GITHUB.md`). Практика разработки: **основные правки в репозитории на рабочей машине**, затем push и деплой; при необходимости правки с сервера **синхронизируются обратно** в Git, чтобы не расходиться с продакшеном.

Дополнительно в репозитории заложены **ресурсы под опции и приложения** (документация в `docs/`, профили Compose, systemd в `deploy/systemd/`, сценарии в `deploy/`).
---

## Разработка: мультиагентная схема (Cursor)

Реализована **мультиагентная** схема ролей в Cursor: **тимлид**, **парсер**, **контент**, **бэкенд**, **фронтенд**. На сервере в продакшене работают **веб (бэкенд + отдача статики)**, **parser-worker**, **content-worker** и **Redis** (`docker-compose.yml`).

---

## Технологии (кратко)

- **Python 3.12**, **FastAPI**, **Uvicorn**
- **Redis** (очереди/стримы для задач парсера и контента)
- **RouterAI** (OpenAI‑совместимый API) — модели для чата, парсера и контента настраиваются в `.env`
- **Docker / Docker Compose** — типовой запуск в продакшене
- Фронтенд страниц: **HTML шаблоны** + **JS/CSS** в `app/static/`

## Быстрый старт (локально)

Требования: **Python 3.11+** (в Docker образе используется 3.12).

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp deploy/env.production.example .env
# при необходимости скорректируйте .env по образцу .env.example
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Открыть:

- `http://127.0.0.1:8000/` — главная / тестовые страницы
- `http://127.0.0.1:8000/consultant` — АЛТ‑эксперт
- `http://127.0.0.1:8000/widget` — виджет для сценариев VK
- `http://127.0.0.1:8000/publapprov/` — согласование публикаций (с авторизацией администратора)
- `http://127.0.0.1:8000/docs` — OpenAPI

Проверка:

```bash
curl -sS http://127.0.0.1:8000/health
```

### Локально через Docker Compose

```bash
cp deploy/env.production.example .env
docker compose build
docker compose up -d
```

## Переменные окружения

- Примеры: **`.env.example`** (локально), **`deploy/env.production.example`** (прод).
- Секреты (**RouterAI**, **VK**, почта и т.д.) хранятся **только в `.env` на сервере** и не коммитятся.

**Важно:** в `.env` не должно быть **дублирующих** строк с одним и тем же ключом (например, дважды `ROUTERAI_API_KEY`). У многих парсеров окружения побеждает **последнее** значение — так легко получить «заглушку» вместо рабочего ключа и **HTTP 401** у провайдера LLM.

## Как работает выбор моделей (main → heavy)

Используется политика **«основная модель → тяжёлая»** для задач, где настроены пары переменных:

- **Бэкенд (чат / синтез):** `BACKEND_MODEL_MAIN`, `BACKEND_MODEL_HEAVY`
- **Парсер:** `PARSER_MODEL_MAIN`, `PARSER_MODEL_HEAVY`
- **Контент (новости / релизы):** `CONTENT_MODEL_MAIN`, `CONTENT_MODEL_HEAVY`

Подробнее о триггерах эскалации и логировании: `docs/MODEL_ROUTING.md`, `docs/ROUTERAI.md`. В JSON‑логах фиксируются модель, токены, назначение вызова и причина маршрутизации (где реализовано).
