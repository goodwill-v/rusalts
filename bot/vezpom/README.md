# ВежПом — бот мониторинга и охраны сроков в МАКС

> Рабочий README агента **Веж** (живой, дополняется по мере развития;
> финальное оформление — в конце проекта). Версия бота: v3.3+.

**ВежПом** — ИИ-помощник в мессенджере МАКС: мониторинг сайтов и серверов 24/7,
контроль сроков (SSL-сертификаты, домены, резервные копии), ежедневный
«светофор», еженедельные отчёты — человеческим языком. Продукт:
`rusalts.ru/techologis/p/vezhpom/`.

## Функционал (текущий)

- **Мониторинг 24/7** (Uptime Kuma): http/ping, алерт в МАКС о падении/восстановлении
  с деталями (код ответа, время отклика);
- **SSL-сертификаты**: автоматом для https-целей, пороги 21/14/7 дней (Kuma);
- **Домены**: RDAP/WHOIS, пороги 30/14/7/1 день, вердикты «срок получен» /
  «домен не найден в реестре (опечатка?)» / «срок не удалось узнать»;
- **Резервные копии**: push-монитор — скрипт бэкапа дёргает пульс
  `https://rusalts.ru/kuma-push/<токен>`, молчание = «копия не создалась»;
- **Анти-шум**: падения — сразу; сроки — вне тихих часов 23:00–08:00 МСК,
  одно сообщение на порог; всё остальное — в светофор;
- **Ежедневный светофор** (09:00 МСК): 🟢/🟡/🔴 одним сообщением;
- **Еженедельный отчёт** (Пн 10:00 МСК): сбои, простой, рекомендации;
- **Журнал событий** для отчётов и метрик простоя.

## Команды МАКС

`/monitor` сайт/IP (https → + SSL) · `/backup` бэкапы · `/domain`, `/domains`,
`/domain_off` домены · `/check` состояние · `/digest` светофор сейчас ·
`/settings` оповещения · `/pay` `/status` `/cancel` `/возврат_средств` `/rules`.

## Тарифы (04.11, решение Шефа)

**Мониторинг 150 ₽ · Страж 500 ₽ · Бизнес 1500 ₽/мес**; «Бизнес+» — кастомное
предложение на странице продукта. Цена/период/триал подхватываются **из Админки
витрины** (`/api/tariff/vezhpom`, кэш TTL 60 с, фолбэк 150/14/30) — в текстах
бота цены не захардкожены. Выбор тарифа и лимиты ресурсов — после доработки
витрины (ТЗ выше), затем гейтинг в боте (агент Веж).

## Архитектура и запуск

```
MAX-пользователь ──/monitor──► бот создаёт монитор в Uptime Kuma (kuma.py, Socket.IO)
Uptime Kuma ──алерт (POST :4321/kuma/<секрет>)──► классификация (vezlogic) ──► МАКС
Домены: domain_watch (RDAP/WHOIS), суточный обход 09:30 МСК
Светофор/отчёт: digest (09:00 / Пн 10:00 МСК)
Подписка: витрина rusalts.ru (vitrina_client) — касса YooKassa
```

| Файл | Назначение |
|---|---|
| `vezpom_webhook.py` | Бот: MAX long-polling + вебхук Kuma (секретный путь) + подписка |
| `kuma.py` | Клиент Uptime Kuma (Socket.IO 1.23.x), защита от гонки add |
| `db.py` | SQLite: users, payments, monitors, domains, events, warnings, prefs |
| `vezlogic.py` | Классификация событий и анти-шум (чистые функции) |
| `domain_watch.py` | Сроки доменов: RDAP/WHOIS, вердикты, суточный обход |
| `digest.py` | Светофор и еженедельный отчёт, планировщик |
| `vitrina_client.py` | Клиент витрины: тариф, подписка, платежи (X-API-Key, fail-open) |

Тесты: `tests/test_vezpom_logic.py`, `tests/test_vezpom_digest.py`,
`tests/test_vezpom_domain.py` (pytest в CI). Локально pytest нет — гоняет CI.

## Деплой (прод: сервер АЛТ)

Пуш в `main` → CI (pytest) → deploy.yml: сайт (docker compose) + бот
(rsync `bot/vezpom/` → `/opt/vezpom/`, рестарт `vezpom.service`,
health `:4321/health`). Секреты — только в `/opt/vezpom/.env`
(образец `.env.example`); юнит — `deploy/systemd/vezpom.service`.

Рабочий клон агента Веж: `/opt/work/vezpom` (в `/opt/alt` не работать —
см. правила координации в `COORDINATION.md`).

## Известные особенности

- Socket.IO-гонка «add»: монитор создаётся, ответ может не успеть —
  `kuma.add_monitor` сам перепроверяет по имени (fix 04.11);
- Сроковые вебхуки Kuma приходят с `monitor=null` — владелец извлекается
  из текста `msg` (fix 04.11);
- Доменные зоны .ru/.su/.рф — только WHOIS tcinet (RDAP-бутстрапа нет);
- Гейтинг тарифов в боте появится после доработки витрины (ТЗ выше).
