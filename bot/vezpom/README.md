## Функционал (текущий)

- **Мониторинг 24/7** (Uptime Kuma): http/ping, алерт в МАКС о падении/восстановлении
  с деталями (код ответа, время отклика);
- **SSL-сертификаты**: автоматом для https-целей, пороги 21/14/7 дней (Kuma);
- **Домены**: RDAP/WHOIS, пороги 30/14/7/1 день, вердикты «срок получен» /
  «домен не найден в реестре (опечатка?)» / «срок не удалось узнать»;
- **Резервные копии**: push-монитор — скрипт бэкапа дёргает пульс
  `https://rusalts.ru/kuma-push/<токен>`, молчание = «копия не создалась»;
- **Анти-шум**: падения — сразу; сроки — вне тихих часов 23:00–08:00 МСК,
  одно сообщение на порог; всё остальное — в светофор;
- **Ежедневный светофор** (09:00 МСК): 🟢/🟡/🔴 одним сообщением;
- **Еженедельный отчёт** (Пн 10:00 МСК): сбои, простой, рекомендации;
- **Проверка ссылок** `/link <url>`: базы угроз (URLhaus) + эвристики
  обмана (IP/punycode/@/опасные TLD); лимит 20/сутки;
- **Диагностика безопасности** `/scan <сайт>` (по согласию владельца):
  TLS, security-заголовки, опасные порты наружу; лимит 3/сутки;
- **Журнал событий** для отчётов и метрик простоя.

## Команды МАКС

`/monitor` сайт/IP · `/monitor_off` отключить · `/backup`/`/backup_off` · `/domain`/`/domain_off` · `/link` проверка ссылки · `/scan` диагностика — и просто пришлите адрес из буфера · `/domain`, `/domains`,

## Тарифы (04.11, решение Шефа)

**Мониторинг 150 ₽ · Страж 500 ₽ · Бизнес 1500 ₽/мес**; «Бизнес+» — кастомное
предложение на странице продукта. Цена/период/триал подхватываются **из Админки
витрины** (`/api/tariff/vezhpom`, кэш TTL 60 с, фолбэк 150/14/30) — в текстах
бота цены не захардкожены. Гейтинг включён (04.11): лимит ресурсов берётся из плана подписки
(`/api/tariffs/vezhpom` → `resource_limit`; общий пул «сайты/серверы + домены»,
бэкап не считается; без подписки — план «Мониторинг». Расход виден в `/status`.

## Архитектура и запуск

```
MAX-пользователь ──/monitor──► бот создаёт монитор в Uptime Kuma (kuma.py, Socket.IO)
Uptime Kuma ──алерт (POST :4321/kuma/<секрет>)──► классификация (vezlogic) ──► МАКС
Домены: domain_watch (RDAP/WHOIS), суточный обход 09:30 МСК
Светофор/отчёт: digest (09:00 / Пн 10:00 МСК)
Подписка: витрина rusalts.ru (vitrina_client) — касса YooKassa
```

| Файл | Назначение |
|---|---|
| `vezpom_webhook.py` | Бот: MAX long-polling + вебхук Kuma (секретный путь) + подписка |
| `kuma.py` | Клиент Uptime Kuma (Socket.IO 1.23.x), защита от гонки add |
| `db.py` | SQLite: users, payments, monitors, domains, events, warnings, prefs |
| `vezlogic.py` | Классификация событий и анти-шум (чистые функции) |
| `domain_watch.py` | Сроки доменов: RDAP/WHOIS, вердикты, суточный обход |
| `digest.py` | Светофор и еженедельный отчёт, планировщик |
| `vitrina_client.py` | Клиент витрины: тариф, подписка, платежи (X-API-Key, fail-open) |

Тесты: `tests/test_vezpom_logic.py`, `tests/test_vezpom_digest.py`,
`tests/test_vezpom_domain.py` (pytest в CI). Локально pytest нет — гоняет CI.

## Известные особенности

- Socket.IO-гонка «add»: монитор создаётся, ответ может не успеть —
  `kuma.add_monitor` сам перепроверяет по имени (fix 04.11);
- Сроковые вебхуки Kuma приходят с `monitor=null` — владелец извлекается
  из текста `msg` (fix 04.11);

# 📘 Как пользоваться ВежПомом (для пользователей)

> Живой раздел: дополняется по мере развития бота. Актуальные цены — из
> Админки витрины; пробный период действует на все функции.

## Зачем ВежПом

ВежПом — бот в МАКС, который следит за вашим сайтом и сервером **круглосуточно**
и пишет вам, только когда это важно: что-то сломалось, вот-вот истечёт срок или
резервная копия не создалась. Остальное время молчит — шумит раз в неделю
коротким отчётом.

## С чего начать (3 минуты)

1. **`/monitor`** → вставьте адрес сайта (например `example.com`).
   Всё: если сайт перестанет отвечать — сообщение придёт через ~2 минуты,
   с кодом ошибки и временем отклика. Для https-сайтов автоматически включается
   контроль срока SSL-сертификата.
Удобно: команды `/monitor`, `/monitor_off`, `/domain`, `/domain_off`, `/link`, `/scan`
работают в два шага — **команда, потом просто вставьте адрес из буфера**.
3. **`/backup`** → бот пришлёт строку-пульс. Вставьте её **последней строкой
   в скрипт резервного копирования** (тот, что делает копии по расписанию):
   ```
   curl -fsS "https://rusalts.ru/kuma-push/<ваш-токен>?status=up&msg=OK"
   ```
   Скрипт сделал копию → дернул строку → ВежПом знает, что всё хорошо.
   **Пульс не пришёл за сутки → вам придёт «Резервная копия не создалась».**
   Это самая частая спасённая беда: бэкапы молча ломаются за месяцы до того,
   как они понадобятся.
6. **`/domain company.ru`** → контроль срока регистрации домена.
   Предупредит за 30, 14, 7 и 1 день. Просроченный домен = сайт и почта
   перестают работать, а вернуть его трудно.
4. **`/link <ссылка>`** → проверка ссылки на фишинг/малварь (базы угроз
   + признаки обмана). Полезно, когда «похоже на развод, но не уверен».
5. **`/scan example.com`** → отчёт по безопасности своего сайта: сертификат,
   заголовки защиты, опасные порты. Сканируйте только свои ресурсы;
   лимит 3 проверки в сутки.

## Что означают сообщения

| Сообщение | Что делать |
|---|---|
| 🔴 `<сайт> — нет ответа (код 500)` | Сайт не отвечает. Смотрите хостинг/сервер; после восстановления придёт 🟢 |
| 🔒 SSL-сертификат истекает через N дней | Продлите сертификат у хостинга/в панели — после истечения браузеры показывают «сайт небезопасен» |
| 🟡 Домен истекает через N дней | Продлите домен у регистратора |
| 🟡 Резервная копия не создалась | Скрипт бэкапа не прислал пульс за сутки — проверьте, что копии вообще делаются |
| 🟡 Домен не найден в реестре | Похоже на опечатку в написании: `/domain_off` и `/domain` заново |
| 📊 Отчёт за неделю (Пн) | Сколько было сбоев и простоя, что починить в первую очередь |

## Ежедневный «светофор» (утро, одно сообщение)

- 🟢 Всё в норме: N сервисов. Я на посту.
- 🟡 Предупреждения: сроки, бэкапы — некритично, но пора заняться.
- 🔴 Проблемы: прямо сейчас что-то не отвечает.

Настраивается: `/settings` (вкл/выкл светофора и отчёта), присылается около
09:00 МСК. Светофор прямо сейчас: `/digest`.

## Отключить что-то

- `/monitor_off <сайт>` — снять мониторинг сайта (без аргумента — список);
- `/backup_off` — отключить контроль бэкапов;
- `/domain_off <домен>` — снять домен с контроля.
