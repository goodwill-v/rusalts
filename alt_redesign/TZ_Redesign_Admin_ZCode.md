## 1. ИДЕОЛОГИЯ ПЛАТФОРМЫ АЛТ («АЛЬТЕРНАТИВА»)

### 1.1 Миссия

**АЛТ — Альтернативные Легальные Технологии.**

Помочь бизнесу, создателям контента и сообществам **легально и эффективно работать в российском цифровом пространстве**, минимизируя риски блокировок и штрафов.

### 1.2 УТП (Уникальное торговое предложение)

Единственный проект, объединяющий три направления под ключ:
1. **Миграция** в отечественные мессенджеры (MAX, VK)
2. **Юридический комплаенс** (152-ФЗ, 168-ФЗ, персональные данные, маркировка рекламы)
3. **Внедрение ИИ-инструментов** (ассистенты, автоматизация, чат-боты)

### 1.3 Позиционирование

> *«АЛТ — ваш юридически безупречный переход в российский цифровой суверенитет»*

### 1.4 Tone of Voice

Экспертный, но доступный. Нейтральный к конкурентам. Акцент на **решения**, а не на проблемы.
Не пугать, а показывать путь.

### 1.5 Целевая аудитория (приоритет)

| Сегмент | Проблема | Боль |
|---------|----------|------|
| **МСБ (ИП/ООО)** | Потеря клиентов из-за блокировок мессенджеров | Штрафы за 152-ФЗ, технические барьеры |
| **Блогеры / инфлюенсеры** | Потеря дохода при блокировках | Сложности с маркировкой рекламы |
| **НКО и сообщества** | Невозможность легально общаться с аудиторией | Требования к хранению данных |

### 1.6 Продуктовая линейка (для понимания контекста)

| Уровень | Что | Примеры |
|---------|-----|---------|
| **L0: Бесплатно** | АЛТ-эксперт (ИИ-консультант), чек-листы, контент ВК | Лидогенерация |
| **L1: Базовые услуги** | Диагностика (2 900 ₽), шаблоны (4 900 ₽), настройка бота (15 000 ₽) | Массовый сегмент |
| **L2: Премиум** | Миграция под ключ (от 75 000 ₽), ИИ-ассистент (от 150 000 ₽) | Корпорации |
| **L3: Подписки** | «АЛТ-защита» (3 900 ₽/мес), «АЛТ-про» (9 900 ₽/мес) | Стабильный доход |

### 1.7 Ключевые принципы дизайна (для ZCode)

При выборе дизайнерских и маркетинговых решений руководствоваться:

1. **Экспертность вместо крикливости** — сайт не «кричит», а внушает доверие. Спокойные тона, чёткая структура, минимум анимации ради анимации.
2. **Технологичность** — проект про ИИ и современные технологии. Дизайн должен это транслировать: чистый, современный, цифровой.
3. **Российский контекст** — сайт ориентирован на российского пользователя. Русский язык, привычные паттерны, но без «колхозного» дизайна.
4. **Доступность** — информация подаётся понятно для неспециалистов. Юридические сложности — простым языком.
5. **Приоритет содержания** — дизайн не мешает контенту. Пользователь должен быстро найти, что ему нужно.

## 3. ЗАДАЧА 1. УНИВЕРСАЛЬНАЯ АДМИН-ПАНЕЛЬ

### 3.1 Цель

Создать единую админ-панель для управления всем сайтом, заменяющую разрозненные интерфейсы.

### 3.2 Мотивация (почему универсальная, а не только витрина)

- Уже есть зачаток биллинг-админки (`admin_billing.html`, `billing_admin.py`) — логично расширить
- Парсер и контент нуждаются в панели для ручного контроля публикаций
- Диагностика, заказы, пользователи — всё ляжет в одну панель
- Единая точка входа для всех админ-задач

### 3.3 Функциональные требования (MVP)

#### 3.3.1 Авторизация
- Вход по паролю/токену (админ не привязан к VK)
- Сессия на базе JWT или cookies

#### 3.3.2 Раздел «Витрина / Товары»
- CRUD для продуктов (название, описание, цена, картинка, платформа, статус)
- Статусы: активен / черновик / архив / скоро
- Просмотр списка заказов (кто, что, когда, оплачено/нет)
- Ручное изменение статуса заказа (подтвердить, отменить)

#### 3.3.3 Раздел «Заказы и подписки»
- Таблица всех заказов с фильтрацией (дата, продукт, статус оплаты)
- Просмотр и управление подписками (активна/заблокирована)
- Ручная активация триала

#### 3.3.4 Раздел «Биллинг»
- Перенести существующий функционал из `admin_billing.html`:
  - Добавление токенов вручную
  - Просмотр баланса пользователей
  - История операций

#### 3.3.5 Раздел «Контент / Публикации»
- Просмотр очереди публикаций (из контент-пайплайна)
- Ручное согласование/отклонение
- Публикация на сайт и в VK в один клик

#### 3.3.6 Раздел «Диагностики» (на будущее)
- Просмотр пройденных диагностик
- Статус обработки (ожидает / обработана / отправлен PDF)
- Контактные данные лида

### 3.4 Технические требования

| Аспект | Требование |
|--------|-----------|
| **Бэкенд** | FastAPI, отдельный роутер `routers/admin.py` |
| **Фронтенд** | Одна страница `admin_panel.html` с табами/секциями (JS-переключение без перезагрузки) |
| **Стили** | В том же `app.css` или отдельном `admin.css` |
| **БД** | Использовать существующую SQLite + добавить таблицы `products`, `diagnostics` |
| **API** | Все операции через REST API /admin/api/* |
| **Безопасность** | Все /admin/ роуты — только после авторизации |

### 3.5 Эталонный роутинг

```
/admin/               — логин / дашборд
/admin/orders/        — заказы
/admin/products/      — управление товарами
/admin/subscriptions/ — подписки
/admin/billing/       — биллинг
/admin/content/       — публикации
/admin/diagnostics/   — диагностики (на будущее)
/admin/api/*          — REST-эндпоинты
```

## 4. ЗАДАЧА 3. РЕДИЗАЙН САЙТА

### 4.1 Цель

Провести ревизию дизайна, улучшить образ, эффектность графики, соответствие современным трендам. Провести рефакторинг CSS и шаблонов для эффективности.

### 4.2 Что не меняем (ограничения)

- **Стек:** FastAPI + Jinja2 + CSS/JS — без перехода на React/Next.js/Vue
- **Структура шаблонов:** наследование через `{% extends "base.html" %}`
- **Язык:** русский

### 4.3 Что делаем

#### 4.3.1 Цветовая схема и визуальный стиль

Создать единую систему через CSS-переменные в `:root`:

```css
:root {
  --color-bg: #f8f9fc;           /* Светлый фон */
  --color-surface: #ffffff;      /* Карточки */
  --color-primary: #1a5c8a;      /* Основной (тёмно-синий) */
  --color-accent: #2ecc71;       /* Акцентный (изумрудный / зелёный — ассоциация с «легальностью») */
  --color-text: #2d3436;         /* Основной текст */
  --color-muted: #636e72;        /* Второстепенный текст */
  --color-border: #dfe6e9;       /* Границы */
  --radius: 12px;                /* Скругления */
  --shadow: 0 2px 8px rgba(0,0,0,0.08);
  --font-body: 'Inter', system-ui, sans-serif;
  --font-heading: 'Inter', system-ui, sans-serif;
}
```

**Акцент — изумрудный/зелёный** (легальность, безопасность, экологичность технологий).

#### 4.3.2 Главная страница (`index.html`)
- **Hero-секция:** крупный заголовок + подзаголовок + CTA-кнопка «Пройти диагностику»
- **Блок преимуществ:** иконки + 3–4 ключевых преимущества (без текстовых полотен)
- **Блок «Как мы работаем»:** 3 шага с иконками
- **Блок продуктов / Витрина:** превью 3–4 продуктов
- **Блок консультанта:** встроенный превью АЛТ-эксперт
- **Футер:** контакты, соцсети (VK, MAX), политика конфиденциальности
- **Подвал для SEO:** юридическая информация

#### 4.3.3 Витрина (`techologis_v2.html`)
Существующая страница — из «песочницы» в полноценный каталог:
- Карточки товаров с изображением, ценой, статусом, кнопкой «Подробнее» / «Купить»
- Фильтрация по категориям/статусам
- Адаптивная сетка
- Страница продукта (как `italidia_product.html`) — улучшить вёрстку

#### 4.3.4 Типовые страницы
- **АЛТ-эксперт** (`consultant.html`): современный чат-интерфейс, чистое поле ввода, аватар, адаптивность
- **Новости** (`news.html`): список с карточками, пагинация
- **Страница публикаций** (`publapprov.html`): таблица + кнопки действий

#### 4.3.5 Рефакторинг CSS

Текущие проблемы (из анализа кода):
1. `app.css` (26 КБ) — монолитный, без переменных, дублирование
2. `showcase.css` (11 КБ) — отдельно, а должен наследовать тему

**Требования:**
- Вынести все цвета/отступы/тени в CSS-переменные (`:root`)
- Разделить на логические блоки (layout, components, pages)
- Удалить дублирующиеся стили
- Обеспечить адаптивность (mobile-first)
- Микро-анимации (hover, transitions, loading states)

#### 4.3.6 Адаптивность
- Desktop: текущая широкая вёрстка
- Tablet: 2 колонки, сжатое меню
- Mobile: 1 колонка, гамбургер-меню, крупные кнопки

### 4.4 Процесс редизайна (рекомендация)

1. **Аудит:** Browser Preview на `rusalts.ru` — ZCode открывает сайт, фиксирует все страницы, оценивает текущее состояние
2. **Создание CSS-переменных и базового style guide** — один goal
3. **Рефакторинг `base.html`** — новый скелет с улучшенным header/footer
4. **Главная** — новая hero + блоки
5. **Остальные страницы** — по одной
6. **Витрина** — финальный штрих
7. **Тестирование** — все страницы на адаптивность

## 5. ТЕХНОЛОГИЯ ДЕПЛОЯ

### 5.1 Процесс

```
Правка → git commit → push в ветку (github.com/goodwill-v/rusalts) →
→ Pull Request в main → CI (тесты) → мёрж → GitHub Actions →
→ SSH на Timeweb → docker compose up
```

### 5.2 Ветки (см. AGENTS.md в корне)

| Ветка | Правило |
|-------|---------|
| `feat/редизайн-главная` | Feature branch для работы |
| `feat/админка-универсальная` | Feature branch для админки |
| `main` | Только через PR, CI зелёный |

**Именование коммитов:** `feat(редизайн): ...`, `feat(админка): ...`, `fix(стили): ...`

### 5.3 GitHub Secrets (для CI/CD)

| Secret | Назначение |
|--------|-----------|
| `SSH_HOST` | Домен сервера (timeweb) |
| `SSH_PORT` | 22 |
| `SSH_USER` | Пользователь сервера |
| `SSH_PRIVATE_KEY` | Приватный ключ для SSH |
| `DEPLOY_PATH` | `/opt/alt` |

### 5.4 Локальный запуск

```bash
cd /opt/alt
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
# .env уже есть на сервере
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
# или через Docker Compose:
docker compose up -d
```

### 5.5 Правила работы (для ZCode)

- ✅ Коммитить в свою ветку (`feat/*`)
- ✅ Открывать PR в main
- ✅ Писать в сообщениях коммитов по-русски
- ❌ Не пушить напрямую в main
- ❌ Не менять `.env`, Dockerfile, `docker-compose*.yml`, `.github/workflows/` без согласования
- ❌ Не форсить пуш, не переписывать историю
